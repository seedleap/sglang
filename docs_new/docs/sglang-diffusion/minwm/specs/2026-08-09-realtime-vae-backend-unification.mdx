# Realtime VAE overlap 后端统一决策

## 决策摘要

Realtime VAE 只保留一套异步调度：`RealtimeLatentHandoffStage` 把 latent 交给
`RealtimeVAEClient`，由持久化 `AsyncVAEWorker` 排队、解码并把帧送回 Gateway。
worker 启动时必须且只能选择一个 decoder backend：

| 部署值 | worker backend | 画质合同 | 会话容量 |
| --- | --- | --- | --- |
| `local` | 无远端 worker | Denoiser 进程内的原生 decoder；默认值 | Denoiser 自身限制 |
| `exact_remote` | `exact` | 原生 causal VAE；目标是保持本地 exact 数值语义 | 固定为 1 |
| `taehv_remote` | `taehv` | TAEHV 近似解码；不承诺 bitwise 或 numerical parity | 可配置多 Session |

不恢复旧的 output-adapter HTTP future，也不在 async worker 内调用另一个 exact HTTP
server。两个远端 backend 互斥，因此不会出现“队列套队列”、重复保序或重复生命周期。
不设置任何参数时仍为 `local`，不会静默把默认画质改成 TAEHV。

## 两套旧实现的关系

### Exact overlap（PR #6）

Exact 路径位于输出侧。Scheduler 返回 Chunk N 后，`RawRGBRealtimeOutputAdapter.send`
在一个 pending output task 中调用独立 HTTP decoder；主循环同时开始 Chunk N+1 的 DiT，
但启动下一次 send 前先等待 N 完成。它是深度为一、严格保序的 future，而不是通用
VAE worker 队列。latent 在 scheduler 路径先同步复制到 CPU，再通过 MessagePack/HTTP
发送；同机优化只把解码后的 raw RGB 响应放进共享内存。

Exact decoder 持有原生 Wan causal VAE。cache 实际挂在共享模型对象的
`_feat_map/_conv_idx` 上，所以它只允许一个活动 Session。已知 `max_chunks` 时 final
chunk 触发清理；断线或无界 Session 原先没有独立的 remote close 合同。

### Async TAEHV（PR #25）

Async 路径位于 latent handoff 层。原实现等到 Chunk N 真正进入 decode actor 才返还
credit；真机 trace 显示，这会让下一块调度等待前一块 decode，只剩很短的尾部重叠。
统一实现改为成功进入每 Session 单槽有界队列后立即返 credit，并把 API 活动 Chunk 上限
固定为两个。因此队列中最多只有一个待解码 Chunk，VAE(N) 可以和 DiT(N+1) 完整重叠，
又不会形成无界预取。一个 WebSocket 覆盖 Session open、latent、credit、frame、final
和 abort 生命周期。同步 decoder 的迭代在 worker thread 中执行，避免 CUDA decode 阻塞
协议事件循环；否则即使 credit 已返还，下一块 latent 仍会卡在 WebSocket 接收侧。TAEHV
权重只读共享，`StreamingTAEHV` context 按 generation 隔离，因此可服务多个 Session。

历史 diff 说明二者职责重复：#25 明确删除了 #6 的 `remote_vae_request` 和
output-adapter 调用，替换成 `realtime_latents/realtime_handoff`。旧 exact server/client
文件虽然一度仍在主干，却没有生产调度入口。`d41d281604` 与 `8ae4e930a3` 的 stable
patch-id 相同，是同一 async 补丁在不同父提交上的版本。

### 为什么选择 async worker 作为统一层

Async worker 已经拥有有界 backpressure、credit、严格 chunk 顺序、Gateway 直传、
reservation、断线 abort、per-generation state 和完整 finally 清理。Exact 只需要实现
相同 engine 接口，不能再复制这些职责。统一后的数据流是：

```text
Chunk N DiT -> latent handoff -> one bounded AsyncVAEWorker queue -> exact | taehv
                     ^                                      |
                     +------ credit / frames / final -------+

同时：Chunk N decode/encode || Chunk N+1 DiT
```

## 状态与语义合同

- 身份：`session_id + generation_id` 隔离 decoder state；`request_id + chunk_index`
  实现严格顺序与重复检测；`event_id` 随输出 envelope 原样返回。
- Credit：latent 通过校验并成功进入单槽队列后返回 `latent_accepted`；队列已满则显式
  backpressure，不能等到 decode 开始才返 credit，否则会把一深度流水线串行化。
- Event loop：同步 exact/TAEHV decoder 的 `decode` 或 iterator advance 不在协议事件循环
  上运行；credit、下一块 latent 接收、frame 发送和 abort 在 GPU decode 期间仍可响应。
- Exact causal cache：Chunk 0 前 reset，后续 chunk 复用；final、abort、断线和 decode
  异常都在 worker `finally` 中 reset。由于 cache 是 model-global，exact worker
  `max_sessions=1`，不得把 TAEHV 的多 Session 交错能力套用到 exact。
- I2V：reference 信息随 handoff 传递，Chunk 0 使用正常 causal first-chunk 语义。
- T2V：worker 保存 Chunk 0 的第一 latent；Chunk 1 把它与常规 latent 拼接，重置并
  重新播种 causal decoder，随后裁掉一个 leading decoded frame。这保留了原来的
  首帧裁剪和展示 chunk index，不把临时 decoder index 暴露给客户端。
- Final：bounded request 在 adapter 中显式标记 final；worker 完成该 chunk 后自然退出。
  无界 Session 由 WebSocket abort/disconnect 清理。
- RGB24：exact 保留原生输出路径的截断量化；TAEHV 保留现有 worker 的四舍五入量化。
- 输出批次：exact 一次原生 decode 产生完整 Chunk，默认预拼 16 帧以减少 shared-memory
  文件和 WebSocket 消息；TAEHV 默认逐帧发送以保留低首帧延迟。两者都可显式覆盖批大小。
- Latent dtype：exact handoff 保留 Denoiser 产出的 dtype，避免在 MinWM decode
  预处理前引入额外精度转换；TAEHV 继续使用 BF16 传输边界。
- Shared memory：loopback URL 的 `auto` 优先把 latent 和返回帧放入同一共享目录；
  路径必须位于配置根目录，读取时校验大小/checksum 并删除。跨主机必须使用
  `websocket`。两个进程必须看到相同 mount 和路径。

## 部署命令

以下命令假设 Denoiser 使用 GPU 0、同机 VAE worker 使用 GPU 1。`/models/minwm`
和 `/models/minwm/vae` 应替换为已校验的 serving artifact。

### Local（默认 exact 画质）

```bash
CUDA_VISIBLE_DEVICES=0 sglang serve \
  --model-path /models/minwm \
  --pipeline-class-name MinWMCausalDMDPipeline \
  --realtime-vae-backend local \
  --port 30000
```

### Exact remote

先启动 GPU 1 worker：

```bash
CUDA_VISIBLE_DEVICES=1 python -m \
  sglang.multimodal_gen.runtime.entrypoints.realtime_vae_server \
  --decoder-backend exact \
  --vae-path /models/minwm/vae \
  --model-path /models/minwm \
  --pipeline-class-name MinWMCausalDMDPipeline \
  --max-sessions 1 \
  --shared-memory-dir /dev/shm/sglang-realtime-vae \
  --host 127.0.0.1 \
  --port 18081
```

再启动 GPU 0 Denoiser：

```bash
CUDA_VISIBLE_DEVICES=0 sglang serve \
  --model-path /models/minwm \
  --pipeline-class-name MinWMCausalDMDPipeline \
  --realtime-vae-backend exact_remote \
  --realtime-vae-worker-url ws://127.0.0.1:18081/v1/realtime_vae/decode \
  --realtime-vae-transport auto \
  --realtime-vae-shared-memory-dir /dev/shm/sglang-realtime-vae \
  --port 30000
```

### TAEHV remote（近似画质）

```bash
CUDA_VISIBLE_DEVICES=1 python -m \
  sglang.multimodal_gen.runtime.entrypoints.realtime_vae_server \
  --decoder-backend taehv \
  --checkpoint-path /models/taehv/taew2_2.pth \
  --max-sessions 8 \
  --shared-memory-dir /dev/shm/sglang-realtime-vae \
  --host 127.0.0.1 \
  --port 18081

CUDA_VISIBLE_DEVICES=0 sglang serve \
  --model-path /models/minwm \
  --pipeline-class-name MinWMCausalDMDPipeline \
  --realtime-vae-backend taehv_remote \
  --realtime-vae-worker-url ws://127.0.0.1:18081/v1/realtime_vae/decode \
  --realtime-vae-transport auto \
  --realtime-vae-shared-memory-dir /dev/shm/sglang-realtime-vae \
  --port 30000
```

TAEHV 是为速度设计的近似 decoder。命令显式选择 `taehv_remote`，健康检查也返回
`decoder_fidelity=approximate`；它不能用于 exact parity 声明。

启动后校验 worker 身份：

```bash
curl --fail http://127.0.0.1:18081/health
```

Exact 应返回 `decoder_backend=exact`、`decoder_fidelity=exact` 和
`max_sessions=1`；TAEHV 应返回 `decoder_backend=taehv`、
`decoder_fidelity=approximate`。worker 与请求 backend 不一致时握手会失败，不会回退。

## 拓扑与性能测量方法

每份性能报告至少记录：代码 SHA、镜像 digest、模型/TAEHV checkpoint hash、GPU SKU、
driver、CUDA/PyTorch、输出格式、尺寸、FPS、每 chunk latent 数、Session 数、warmup 数和
共享内存 mount。首先保存拓扑：

```bash
nvidia-smi topo -m
nvidia-smi --query-gpu=index,name,pci.bus_id,memory.total \
  --format=csv,noheader
```

同机推荐 GPU 0 跑 DiT、GPU 1 跑 exact/TAEHV，并确认两者没有意外的 CUDA_VISIBLE_DEVICES
映射。跨节点测试同时记录 RTT 和 latent/frame wire bytes。

测量时先完成至少 20 个 warmup chunk，再固定输入测 200 个 chunk；分别报告
`denoise_ms`、`queue_wait_ms`、`latent_send_ms`、`decode_ms`、`encode_ms`、首帧延迟、
chunk 端到端 p50/p95/p99 和峰值显存。用 trace 或 Nsight Systems 验证时间线上确实存在
`VAE(N) || DiT(N+1)`，并确认每 Session 最多一个待解码 chunk、输出仍按 chunk index
严格有序。吞吐对比必须同时包含 local、exact_remote 和 taehv_remote；不能把 TAEHV
结果作为 exact 加速比。

## 2026-08-10/11 三硬件验证结果

正式矩阵固定同一 checkpoint、seed、prompt、action 与请求合同：`1248x704`、BF16、
4 denoise steps、KV45、raw RGB、20 warmup + 200 measured chunks。单节点申请 8 张 GPU，
DiT 使用 GPU 0–3 按 SP1/SP2/SP4 扫描，双 GPU exact spatial worker 固定使用 GPU 6–7；
H100、B200、B300 节点内均为 NV18 全互联。运行时固定为 PyTorch 2.11.0+cu130、
Transformers 5.12.1、Diffusers 0.37.0。

| GPU | local SP1 | exact remote SP1 | exact remote SP2 | exact remote SP4 | 24 FPS |
| --- | ---: | ---: | ---: | ---: | --- |
| H100 80GB | 8.656 | 16.905 | **23.652** | 20.764 | 本节点略低；另一 H100 节点 SP2 为 25.279 |
| B200 | 13.875 | **27.183** | 未运行 | 未运行 | SP1 达标 |
| B300 SXM6 AC | 14.725 | **29.905** | 未运行 | 未运行 | SP1 达标 |

H100 的 SP4 低于 SP2，说明在该 5B/720p shape 上继续增加 DiT Ulysses 通信不是单调收益。
两次 H100 SP2 的 `23.652` 与 `25.279` 相差约 6.4%，因此 24 FPS 应报告为跨节点临界值，
不能只引用最好的一次。B200/B300 的双 GPU exact worker 相对 local 分别为约 1.96x/2.03x。

worker Prometheus 前后快照按每 lane 220 个 chunk 求差，得到：

| GPU / lane | queue wait | exact decode | frame encode（GPU RGB8 + D2H） |
| --- | ---: | ---: | ---: |
| H100 / DiT SP1 | 0.154 ms | 431.87 ms | 32.87 ms |
| H100 / DiT SP2 | 0.182 ms | 438.16 ms | 32.86 ms |
| H100 / DiT SP4 | 0.179 ms | 454.89 ms | 33.21 ms |
| B200 / DiT SP1 | 0.117 ms | 268.81 ms | 27.19 ms |
| B300 / DiT SP1 | 0.108 ms | 267.52 ms | 25.91 ms |

queue 几乎为零，证明 credit-on-admission 与单槽队列没有形成排队瓶颈。RGB 路径在 GPU 上
先 clamp/量化为 uint8，再只搬运约 40.2 MiB/16 帧，而不是约 160.9 MiB float32；当前
`frame_encode` 指标把 GPU RGB8、D2H 和 payload 构建作为一个阶段记录。

### Numerical parity

spatial partition 会改变 BF16 浮点运算/归约顺序，因此结果不是 bitwise equal。硬件实测后
把 numerical gate 明确校准为 `max_abs <= 8/255 && sampled PSNR >= 58 dB`，两个条件必须
同时满足；bitwise 状态继续单列，不能把 `exact` 误写为 bitwise：

| GPU | sampled max abs | sampled mean abs | sampled PSNR | numerical parity |
| --- | ---: | ---: | ---: | --- |
| H100 | 5 | 0.02766 | 63.71 dB | pass |
| B200 | 7 | 0.07443 | 59.33 dB | pass |
| B300 | 5 | 0.06879 | 59.74 dB | pass |

B300 首个 `-08` Job 因 Kubernetes `activeDeadlineSeconds` 把约 5 小时 45 分的 Spot Pending
时间也计入，拿到机器后在本地 lane 中途被终止。`-09` 将 B300 deadline 延长到 48 小时，
复用同一 Spot 节点后正常完成。这个 deadline 是 Job 生命周期，不是 GPU kernel timeout。

## 验收门槛与剩余 GPU gate

CPU 可验证部分包括 backend/transport 参数互斥、协议版本、顺序/final、断线和异常清理、
exact 单 Session 容量、T2V reseed/crop、shared-memory 路径/大小/checksum/删除、最小
WebSocket 集成与部署 manifest。

三种目标 GPU 的 I2V 固定输入吞吐与 numerical parity 已完成。继续进入生产前仍需：

1. I2V 与 T2V 的 Chunk 0、Chunk 1 reseed/crop 和 final chunk 视觉回归；
2. TAEHV 视觉质量评测，并明确标记为近似结果；
3. Nsight 时间线补充 DiT/VAE overlap、显存和通信 kernel 证据；
4. loopback shared memory、跨节点 WebSocket、客户端进程崩溃后的孤儿文件清理演练。

当前可以声明三硬件 I2V numerical parity 与上述固定合同下的吞吐收益；在剩余 gate 完成前，
不能扩大为 T2V、TAEHV 画质或跨主机生产可靠性的结论。
